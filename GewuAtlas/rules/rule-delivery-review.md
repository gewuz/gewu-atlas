# 交付物内容评审

自评与独立只读盲审共用本规则。以原始任务核定本轮新增、修改及明确要求交付的对象，将完整清单随 --note_refs 提交。只用于取证的来源单列。算子只生成待审清单，审阅者实读正文后填写结果。

## atomic

完整性（15）看一卡能否独立陈述一个主张及其适用边界。真实性（15）看依据如何支持主张，OBJ 核事实与条件，SUB 核判断依据与取舍，SYN 核多源关系与推导，HYP 核预测及可证伪条件。可读性与脱敏（10）看术语清楚、正文可独立理解、无本机路径，段落数依论证需要决定。

## moc

完整性（15）看全文是否围绕课题问题展开，结尾交代已解释的问题、尚缺的证据和下一步如何验证。真实性（15）核对连接各卡的因果、比较或递进关系，标明推断与分歧。可读性与脱敏（10）检查段落衔接、双链在句中的读法和 Markdown 渲染，可用 alias 自然行文，排除裸露标记、截断注释及本机路径。

## artifact

完整性（15）逐项对照原始任务、目标读者、用途和约定格式，检查成果是否可直接使用。真实性（15）回查关键结论、数字与建议，注明适用条件和不确定性。可读性与脱敏（10）检查结构能否帮助读者找到结论、理解依据并采取所需行动，检查本机路径泄漏。

## 审阅回执

先列范围和审阅方式。逐件给出句柄、类型、三个维度的分数、PASS 或 FAIL、正文定位和判定理由；有缺陷时写明修订动作。抽查列明选择理由、已审及未审句柄，部分覆盖记 PARTIAL。已发现的 FAIL 单列，不能用平均分抵消。

随后从交付物的关键断言沿实际引用实读到依据，记录「断言位置 → 引用卡及原文位置 → 支持、部分支持、矛盾或缺证」，核对限定条件有无在转述中丢失。允许直接引用原始文献；无跨卡依赖时说明原因。关键结论无据、虚构证据、把假设写成事实、遗漏核心诉求或泄露物理路径，判相关对象 FAIL。只有硬评 60/60、范围全覆盖、逐件通过且关键证据链成立，才签发整体 PASS。

## 自评与盲审的执行方式

可调用 Subagent 时，交给独立只读审阅者，提供原始任务、完整对象清单、正文与可回查的来源，不提供作者的预期分数或自我辩护。无法调用时显式标记「自评」及原因。两者采用相同量表与通过条件。

自评先仅从用户请求列出可验证的验收问题，再重新打开当前版本正文，逐项找出回答这些问题的具体段落。对决定结论的主张尝试反证，例如回到原文检查一项遗漏的前提、相反数据或替代解释，记录实际查过的位置、发现和对结论的影响。若无法访问依据，标记缺证。修订后重读改动段落及依赖该结论的卡，再更新判定，保留首次发现与复核结果。

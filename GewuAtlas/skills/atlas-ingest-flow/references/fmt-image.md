# 图片与工程图：物理抽取与视觉理解

默认脚本读取位图尺寸/格式/元数据；SVG 文本和节点；Draw.io XML（含压缩页面）节点与连线标签；Excalidraw 文本元素。输出原图引用与结构化伴生文档。位图不会自动 OCR，节点文本不等于理解图意。

图片导读、伴生卡与 deep 才进行视觉加工。先 fmt-assets 获取明确的公开预览，调用宿主视觉工具；无视觉工具或无法辨认时如实标为未完成。不得把元数据抽取冒充 OCR。

四轮检查沿用 R6 的认知漏斗：

1. 宏观：所属章节、图类型、目标、主要分区/泳道、起点与范围。
2. 要素：逐一核对可见模块、接口/协议、字段、版本、图例、坐标轴、单位、数值与角落注释；模糊文字标未知。
3. 关系：数据/控制流、依赖/包含、条件/异常分支与边界。可用 Mermaid 表达时输出对应图；照片等不适用，不强画。
4. 反查：将每个元素/数值与原图比对，检查遗漏，区分正文已知事实与图示推断，生成短导读及完整要素矩阵。

独立卡包含父卡来源引用、原图引用、描述、矩阵与适用图代码；父卡保持原图和指向伴生卡的链接。通过 note-create/note-link/fmt-apply-window 完成，不调用 R6 的物理路径会话文件，不另建状态机。默认模式不自动开启四轮问答或伴生卡扩展。

职责与调用总则以 [atlas-fmt](../SKILL.md) 及 [commands.yaml](../../../dicts/commands.yaml) 与 [rule-core-vfs.md](../../../rules/rule-core-vfs.md) 为准。本参考的语义加工步骤仅在 deep 或明确要求相应加工时执行。

复合容器支持：Draw.io PNG 的 mxfile 元数据、SVG 的 content 属性；Excalidraw PNG/SVG 的嵌入场景（原始或 bstring/zlib 编码）。不含源数据的工程图片拒绝伪装成解析成功，可另按普通图片导入并明确只做视觉加工。Obsidian .excalidraw.md 支持可读 Text Elements 与 JSON；只有 compressed-json 时需先导出原生 .excalidraw，当前不解码该格式。压缩元数据展开上限为 20 MiB。

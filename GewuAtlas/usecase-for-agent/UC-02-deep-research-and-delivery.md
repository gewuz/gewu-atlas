## 1. 适用场景与触发信号

- 收到专向课题研究（`prj_XX`）、多篇系列报告/教程撰写、成果采收（`artifact-adopt`）与定稿（`artifact-finalize`）任务时必读。
- 触发词：自主研究、不止一篇、权威文档、完成整个课题、报告交付、人类阅读观感优化。

## 2. 高频损耗 → 直通对策

| 损耗点 | 上次表现 | 下次直通做法 |
| :--- | :--- | :--- |
| **正文堆砌行内句柄与 `[客观]` 类机械标签破坏可读性** | 正文夹杂 `【官方事实】`、`【综合推断】`、`[客观]` 与密集的 `（nte_733、nte_769）`，导致视觉割裂、行文为凑标注而变形，严重拉低人类阅读观感 | **正文保持纯粹流畅的人类散文体验**：严禁在成果报告正文中插入 `[客观]`/`【官方事实】`/`【综合推断】` 等机械分类标签，也不在正文句子与表格单元格内散落 `（nte_XX）` 行内引用；用自然语言区分事实与推论（如「Anthropic 实测表明……」「基于上述机制可推算……」），全部 `nte_XX` 与原件溯源统一沉底至文末 `## 参考来源与知识库索引` |
| **盲审滞后导致多轮返工** | `adopt` 后再盲审 → 改 1 行 → 再 `update` + `finalize`，多花 2 轮变更 | **将验收前置到 `drafts` 草稿阶段**：先在 `ws-<agent>/drafts` 完成 `guard --mode delivery` 与盲审/自评，改完后一次性 `adopt` |
| **长切片句柄视觉噪音** | 正文裸写长串切片文件名，阅读体验差 | 正文彻底不写切片句柄；仅在文末参考区按主题分组列出短句柄与人类可读标题，需要双链跳转时用 `[[note_name\|短名]]` 管道别名 |
| **回执刷屏挤占上下文** | 逐张单读卡片导致数十行 JSON 刷屏 | 一律用 `python3 - << 'PY'` 批量 `note-get --note_refs nte_01,nte_02,...` 并在管道里截断单卡长度（1000~1500 字） |
| **交付前无量化证据** | 只写「已通过」，无法自证 | 收尾跑**四段校验**：① `guard --mode delivery`（应 60/60）；② 从文末参考区抽取全部 `nte_XX` 做 `note-get` 批量核验（应 N/N 全存）；③ 扫描正文不含 `[客观]`/`【官方事实】` 与行内句柄；④ 路径泄漏正则扫描应为 0 |
| **自评只给结论** | 写「真实性 15/15」却无依据 | 把 rubric 逐项写进回执：完整性 / 真实性 / 可读性与零路径各配一句核验事实 |

## 3. 黄金流水线与高分交付配方（冲刺 95+ 分 · 兼顾严谨溯源与顶级阅读体验）

1. **一步开课题配工作台**：`./gewu.command atlas --action project-create --ref <vlt_01> --title "<课题>" --agent <名>`（直接从返回体拿 `ws-<agent>/drafts`）。
2. **三篇报告固定正交分工**：多篇交付时按 **「机制原理篇 / 全景对比篇 / 决策与边界篇」** 正交分工，直接复用原子卡底层证据但彻底按深度技术专栏文风重新组织叙事。
3. **正文纯净叙事 + 文末集中溯源**：正文**零 `[客观]`/`【官方事实】`/`【综合推断】` 标签、零行内 `nte_XX` 括号噪音**，以自然流畅的同行专家语言交代出处与推论边界；每篇配 2 个可复算工程案例与安全双引号 Mermaid 图；所有 `nte_XX` 逻辑句柄与 MOC/原子卡链接集中收敛于文末 `## 参考来源与知识库索引`。
4. **验收清单预检**：算子 60 = 空间净空 15 + Schema 15 + 双链与引用真值 15 + 审批治理 15；软评 40 = 完整性 15 + 真实性 15 + 可读性与零路径 10（重点把关语言流畅度与无机械标注干扰）。
5. **收尾脚本一次跑完**：四项硬检 + 盲审签发 `PASS` 后，单脚本串行完成微修、`artifact-adopt` 与最终 `guard`。
6. **交付回执结构**：结论先行 → 交付物句柄清单 → 核心结论 2~3 条 → 量化证据 → 待确认项（`artifact-finalize` 须人类拍板）；不贴长表格，不复述算子原始 JSON。

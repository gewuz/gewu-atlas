# 多报告深度研究、前置盲审与高分交付路书

## 1. 适用场景与触发信号

- 收到专向课题研究（`prj_XX`）、多篇系列报告/教程撰写、成果采收（`artifact-adopt`）与定稿（`artifact-finalize`）任务时必读。
- 触发词：自主研究、不止一篇、权威文档、完成整个课题、报告交付。

## 2. 高频损耗 → 直通对策

| 损耗点 | 上次表现 | 下次直通做法 |
| :--- | :--- | :--- |
| **盲审滞后导致多轮返工** | `adopt` 后再盲审 → 改 1 行 → 再 `update` + `finalize`，多花 2 轮变更 | **将验收前置到 `drafts` 草稿阶段**：先在 `ws-<agent>/drafts` 完成 `guard --mode delivery` 与盲审/自评，改完后一次性 `adopt && finalize` |
| **长切片句柄视觉噪音** | 正文裸写长串切片文件名，阅读体验差 | 正文用 `（nte_XX）` 行内标注即可；需要双链时用 `[[nte_XX\|短名]]` 管道别名，兼顾溯源与排版 |
| **回执刷屏挤占上下文** | 逐张单读卡片导致数十行 JSON 刷屏 | 一律 `note-get --note_refs nte_01,nte_02,...` 单次批量读，并在管道里截断单卡长度（1000~1500 字） |
| **交付前无量化证据** | 只写"已通过"，无法自证 | 收尾跑**三段校验**：①`guard --mode delivery`（应 60/60）；②从草稿 `grep -oh 'nte_[0-9]+'` 取全部引用，`note-get` 批量核验（应 N/N 全存）；③`grep -c '/Users/\|/<受控卷>/\|\.local/'` 应为 0 |
| **引用密度失控** | 为显得有据而堆句柄 | 单篇 8~10 个句柄、三篇合计 ≤25；超出说明在拼贴检索结果而非论证，应删冗余引 |
| **自评只给结论** | 写"真实性 15/15"却无依据 | 把 rubric 逐项写进回执：完整性/真实性/可读零路径各配一句核验事实（如"24/24 句柄实存""路径泄漏 0"） |

## 3. 黄金流水线与高分交付配方（冲刺 85~95 分）

1. **一步开课题配工作台**：`./gewu atlas --action project-create --ref <vlt_01> --title "<课题>" --agent <名>`（直接从返回体拿 `ws-<agent>/drafts`）。
2. **三篇报告固定分工**：多篇交付时按 **「机制原理篇 / 全景对比篇 / 决策与边界篇」** 正交分工，直接复用原子卡「断言 → 机理证据 → 边界权衡」三段式。
3. **三级事实与可复算案例**：正文显式标注 **「官方事实 / 第三方实现 / 综合推断」** 三级真值与来源句柄；每篇至少 2 个可复算案例或判断自测题；附研究链路 Mermaid 图（入库 → 萃取 → 成文）。
4. **验收清单预检**：算子 60 = 空间净空 15 + Schema 15 + 双链与引用真值 15 + 审批治理 15；软评 40 = 完整性 15 + 真实性 15 + 可读与零路径 10。按这七项逐条自检后再 adopt。
5. **收尾三段脚本一次跑**：guard → 引用真值批量核验 → 路径泄漏 grep，在同一轮内完成，避免三次往返。
6. **交付回执结构**：结论先行 → 交付物句柄清单 → 核心结论 2~3 条 → 量化证据 → 待确认项；不贴长表格，不复述算子原始 JSON。

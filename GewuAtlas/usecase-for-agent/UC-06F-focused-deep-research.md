## 1. 适用场景与触发信号

- 用户以**一句话问题**进入，且明确要求「快、准、能拿去决策」：如「多语言栈该不该合仓、选哪套构建工具」「跨仓版本拉扯怎么解」。
- 触发词：ChatGPT Deep Research、聚焦研究、先确认再研究、3–5 个问题对齐、出大纲再执行、决策级白皮书。
- 与 **UC-05D 扩散研究**的分工：扩散是广撒网建库、交付后供人类长期自由检索；聚焦是先对齐问题域、只采该范围内的证据、交付一份成品。**同题可串联**：先扩散建底库，再聚焦直接挂载上游底库出决策件。

## 2. 高频损耗 → 直通对策

| 损耗点 | 表现 | 下次直通做法 |
| :--- | :--- | :--- |
| **跳过需求对齐直接开搜** | 未问清楚主体约束/痛点/落点/形态就检索，方向偏后整份报告返工 | 开工即 `interaction_ask` 抛 4 问（决策主体与约束、核心痛点、目标落点、交付形态）；这 4 个答案直接决定检索词与章节 |
| **库内检索参数互斥** | `note-search` 同时传 `--ref` 与 `--all_vaults`，`E_PARAM_INVALID` 熔断 | 单库只传 `--ref`，跨库只传 `--all_vaults`，二者不共现 |
| **采集三类非预期失败** | PDF 直链 403；案例页正文 130 字被判空壳自动删除；境外博客 TLS/超时 | 失败**不重抓**：保留 URL，用 `general_search` 摘要作「旁证」，正文与附录显式标注「未入库」及原因；若核心信源大面积失效则触发异常熔断 |
| **长文写入被误判为失败** | 3 万字级 `note-create` 超 15s 前台预算被转后台 | 写作类调用默认预期后台化，`TaskOutput` 轮询，**不要重复提交** |
| **附录只分层不给链接** | 人类当场要求「证据分级要加上链接」返工 | 每条固定三段：`[标题](URL)` + 库内 `nte_XX` + 关键数字摘要；厂商自评单列一组 |
| **厂商互评的自利偏差** | Nx 评 Bazel 强调维护成本、Vercel 评 Nx 强调配置复杂度 | 取**三方共识**作结论，单家结论只作旁证，并在争议章点名偏差来源；成稿后执行轻量级去偏核查 |
| **大纲后过度请示** | 每步都回头确认，节奏拖沓 | 人类回「可以」即视为放行，直接进第四步（仅在触发异常熔断时主动暂停汇报） |
| **范围漂移后不补采** | 中途扩大问题域，旧证据覆盖不到新章节 | 范围一变先补 `ingest` 差量，再动笔；否则宁可缩回原范围 |

## 3. 黄金流水线（五步）

1. **自评 + 双语料盘点（含上游串联分支）**：
   - **串联分支**：若上游存在已完成的 UC-05D 扩散研究课题，直接挂载上游产出的 `prj_XX`、原子卡与 MOC 地图作为基准语料，跳过公网初扫，直接进入第 2 步。
   - **独立分支**：`note-search`（单库模式）扫库 + 2–3 路公网扫描，先报「库内沉淀几条 / 缺口在哪」，再谈方向。库内零沉淀要直说，别用语义误召的条目充当依据。
2. **需求对齐**：一次 `interaction_ask` 抛 4 问：决策主体与约束（如团队规模与技术栈）、核心痛点（可多选）、目标落点、交付形态与深度。
3. **定向补搜 + 章节级大纲**：只补对齐后仍缺的证据；大纲每章写明「核心问题 / 拟用证据 / 待补证据」，并预告哪些结论只能以旁证形式出现。大纲即人类主要的低成本纠偏点。
4. **入库 → 切片 → 萃取 → 织网（含异常熔断）**：`project-create` 先落工作台（若已挂载上游底库则复用）；`ingest` 分两批、每批 ≤5 URL（单个超长页会吃掉切片额度）；`atomic-extract` 出 4–5 张卡，覆盖「收益 / 成本 / 正确性 / 策略」四类；`moc-sync` 用统一 tag 织成决策地图。
   - **异常熔断钩子**：若此阶段遇到核心数据源全部 403 失败、多方数据严重冲突，或关键结论只能靠「未入库旁证」支撑时，主动暂停向人类汇报，由人类决定放宽范围补采还是降级结论。
5. **成稿 → 轻量核查 → 验货 → 采收**：长文 `note-create` 后台写入；执行**轻量级事实核查与去偏盲审**（重点校验核心结论是否基于三方共识、旁证是否被越界写成硬结论）；`guard --mode delivery` 取 60/60；`artifact-adopt` 采收；`present_files` 交付；附录三件套齐全。

## 4. 交付物形态

决策级白皮书 10 章骨架（技术/架构选型参考模板，非技术类决策可按目标落点裁剪）：摘要三条结论 → 诊断（把症状拆成可计价成本）→ 收益与成本的交叉点 → 分层地图 → 持有成本 TCO → 策略与阈值 → 正确性风险 → 迁移/实施阶段 → 度量与反指标 → 争议与未解 → 决策线 + 核查清单。

写作纪律：结论先行；每个判断配一个可测数字或可执行判据；推荐结论必须并列「放弃条件」；证据分级单列一章，明确哪些数只作方向性参考。

## 5. 边界：什么时候该改走扩散研究

- 问题域还说不清、需要横向铺开比选，或资料要长期复用 → 走 UC-05D，先建库。
- 聚焦模式的固有代价：**范围窄即证据窄**，超出问题的材料不会被采集；中途扩容要先补采。
- 若交付后人类提出「再多给我一些行业背景」，说明问题已扩散，应转扩散模式补库，而不是在旧稿上堆砌。

# 契约：Markdown 分级排版、混排与文本写作规范（`gewu.markdown-formatting/1`）

本契约是 `GewuForge` 与所有由其生成的格物域（Domain）编写 Markdown 文档、规则、契约、技能与交付报告的静态排版基线。目标在于同时满足**零依赖脚本/Agent 无歧义解析**与**人类专家高精度可读性**，消除大模型的机械化套路与排版噪声。

所有文档共同遵循一条跨客户端底线：以标准纯文本 Markdown + 可选 YAML Frontmatter 为唯一载体，不依赖任何特定客户端（如 Obsidian 私有扩展）才能正确阅读核心结论。

---

## 1. 结构复杂度分级（Formatting Tiers）

依据目标受众与解析优先级，将文档划分为三档排版复杂度：

### 1.1 Tier 1 协议与契约层

- **适用范围**：`AGENTS.md`、`rules/`、`contracts/`、`skills/*/SKILL.md`、对象规格与 CLI/API 协议说明。
- **核心要求**：机器与 Agent 解析优先级最高，零结构歧义。
  - 各级标题与前后段落之间、段落与段落之间保留且仅保留一个空行；
  - 无序列表统一使用 `-`，子级缩进固定为 `2` 个半角空格（禁用 Tab）；
  - Fenced 代码块必须显式标注语言标签（如 `bash`、`yaml`、`json`、`text`）；
  - 允许元素：标准 ATX 标题（`#` ～ `####`）、正文段落、嵌套列表、行内代码、Fenced 代码块、YAML Frontmatter，以及**单层紧凑 GFM 路由/对照表**（例如 `AGENTS.md` 场景路由表、决策矩阵）；
  - 禁用元素：跨行跨列复杂合并表、内联 HTML 装饰标签（`<div>`、`<span>`、`<br>` 滥用）、多层折叠 Callout 与表情符号装饰。

### 1.2 Tier 2 域资产与工程记录层

- **适用范围**：业务域数据卷 Markdown（如工单单据、原子笔记、索引 MOC、演进记录、测试与验收纪要）。
- **核心要求**：结构稳定、因果明确、支持脚本与人类双向核验。
  - 若文档定位为单点概念卡或独立记录，聚焦单一主题与事实证据链，避免冗长发散；
  - 图表优先使用纵向自上而下的 `flowchart TD`（节点短标签建议 ≤ `10` 字，避免窄宽视口下横向失真）；
  - 允许轻量对照表（`2`～`4` 列）与单层标准 Callout（如 `> [!NOTE]`、`> [!WARNING]`、`> [!CAUTION]`）；
  - **可选双链规范（针对启用 Wikilink 的域）**：正文中引用卡片或实体直接裸写 `[[...]]`，严禁外包反引号（反引号会切断图谱与链接解析）；当物理文件名带域/主题前缀时，正文中优先使用管道别名语法 `[[目标全名|自然概念名]]`，外侧与汉字之间保留 `1` 个半角空格；普通文档域统一使用标准 Markdown 相对链接 `[显示名](路径)`。

### 1.3 Tier 3 架构设计与交付报告层

- **适用范围**：架构规划书、技术评审报告、用户面向制品（Artifact）与多维看板视图。
- **核心要求**：面向人类高维决策，在保持纯文本自足的前提下充分释放表现力。
  - 全面支持 GFM 多列表格矩阵、可折叠 Callout（`> [!NOTE]- ...`）、`sequenceDiagram` / `stateDiagram-v2` / `erDiagram` 与图文结构化注释；
  - 时序图角色建议用简短别名（如 `actor P as Provider`），消息短文本收敛，避免无谓拉宽；
  - 核心结论与决策依据必须在普通 Markdown 渲染中 100% 独立可读，不向客户端私有方言（`.canvas`、`.base` 等）形成排他性依赖。

## 2. 排版、中西文混排与引号契约

### 2.1 边界留白（Pangu Spacing）

- **汉字与西文/数字**：中文字符与英文字母、半角数字之间保留 `1` 个标准半角空格（如 `调用 GewuTrack 接口`、`提升 30% 吞吐量`）；
- **行内代码与链接**：行内代码（`` `cmd` ``）或链接（`[text](path)`）紧邻汉字时，外侧保留 `1` 个半角空格（特殊标点紧贴除外）；
- **数值与单位**：度量衡单位与数值间保留半角空格（`16 GB 内存`、`200 ms`）；`%` 与 `℃` 紧贴数值（`99.9%`、`25℃`）。

### 2.2 全半角标点与引号弹性规范

- **标点体系**：中文正文句内与句末使用全角标点，不在全角标点两侧滥加额外空格；中文省略号用 `……`，破折号用 `——`。
- **引号选择（弹性约定）**：
  - 中文正文**可使用标准中文弯双引号 `“”`（嵌套时用 `‘’`）或直角引号 `「」`（嵌套时用 `『』`），不强制要求使用 `「」`**；
  - 同一篇文档或同一批次产出内，建议保持引号风格前后一致；
  - CLI 参数示例、JSON/YAML 字面量与代码块内部始终使用标准半角引号 `"` / `'`，中文叙事正文避免混用无配对的半角直引号 `""`。

### 2.3 专有名词与缩略语

- 品牌与技术名称按官方大小写保真（如 `GitHub`、`macOS`、`JavaScript`、`TypeScript`、`PostgreSQL`、`GewuForge`、`GewuTrack`、`GewuTicket`）；
- 非常识英文缩略语首次出现时注明全称与中文释义，如 `IPC（Inter-Process Communication，进程间通信）`。

### 2.4 行内样式与全角标点冲突熔断

CommonMark 解析引擎在行内修饰符（`**...**`、`~~...~~`、`<u>...</u>`）内侧紧贴全角标点（`“”`、`「」`、`（）`、`《》`、顿号、逗号、分号）时，易触发定界符闭合失败并直接暴露原始 `*` / `~` 符号。执行两级硬处理：

1. **内侧纯净原则**：`**`、`~~`、`<u>` 定界符内侧首尾紧贴汉字、英文字母或半角数字，不紧贴任何标点。
2. **全角标点 ≤ 2 个 → 标点外置**：将成对引号、括号、书名号移至修饰符外侧：
   - 正确：`“**符合预期**”`、`「**符合预期**」`、`《**技术规范**》`、`**扩展模式**（Extended Mode）`、`~~旧概念~~（已废弃）`；
   - 禁止：`**“符合预期”**`、`**「符合预期」**`、`**（Extended Mode）**`、`~~旧概念（已废弃）~~`。
3. **全角标点 > 2 个 → 彻底熔断**：跨度较长且内部包含超过 `2` 个全角标点时，禁止整段加粗或加删除线，改回纯文本叙述或仅对其中无标点核心词做局部强调。

## 3. 标题构建与序号分级

标题中的数字仅允许用于**客观结构编号**，禁止作为**修辞性量词堆砌**。

1. **序号三大互斥通道**（单篇文档只选其一，禁止混用）：
   - **西式数字通道**（`1.` → `1.1` → `1.1.1`）：适用于规范、契约、工程方案、API/CLI 文档、操作手册；
   - **中式汉字通道**（`一、` → `（一）` → `1.`）：适用于正式汇报、制度说明；
   - **无序号纯概念通道**：标题直接由实体或机理短语构成，适用于原子卡、摘要页与叙事文本。
2. **量词修辞绝对禁令**：禁止在标题与纲要中拼凑“几大核心”“三大原则”“四大支柱”“五步走”“八部曲”等修辞凑数（如将“三大核心设计原则”改写为“设计原则与边界约束”）。允许客观结构编号（`1.1`）与实测工程度量（`1 MiB`、`8 ms`、`12 万 QPS`）。
3. **标题行末净化**：各级 Markdown 标题行末不加句号、逗号、冒号、分号或叹号。

## 4. 全局文本反模式熔断（Anti-Pattern Fuses）

1. **语态对等，剥离主持报幕**：使用同行工程师/专家记录的平实冷静口吻；禁止“非常荣幸为您解答”“希望能帮到您”等套话，禁止“在当今快速发展的时代”“众所周知”“总而言之”“综上所述”“未来可期”等空洞串场与尾部升华；结论段只交付动作结果、影响范围与未决风险。
2. **事实推进，禁止虚构对照**：禁用“不是 X，而是 Y”“与其说 X，不如说 Y”二元修辞对立句；按“观察事实 → 机理与代价 → 选型与定论”直陈；用行为动词消除“针对……进行分析”“实现对……的提升”等冗余介词。
3. **禁止正文凑数与虚假排比**：现实有几条依据就列几条，禁止为凑齐三段排比或对称工整而硬造伪概念；禁用“底层逻辑”“深度赋能”“协同共生”“本质上”“颠覆性”“至关重要”等通胀黑话。
4. **遏制无靶防守与伪深刻警句**：不虚设假想反对者再自我反驳，有适用条件直接明写边界条件。
5. **句长突发度与节奏控制**：交错短断句（下定论）与复合长句（展推导），避免整篇段落长度与连接词（“不仅……而且……”）高度均质。

## 5. 业务文类核心契约

- **技术方案与架构研报**：主动语态、双向权衡（陈述收益同时明确牺牲的延迟、复杂度或维护成本）、指标与代码事实紧跟论点之后。
- **工程规格与契约文档**：零模糊副词（禁用“极速”“丝滑”“友好地”），显式穷尽前置条件、输入域、状态转移与失败回滚行为（Given / When / Then）。
- **操作手册与 Runbook**：动作动词前置；危险及不可逆操作在指令前使用 `> [!CAUTION]` 警示块；每步提供可核验的成功态输出特征。
- **英文技术写作**：标题采用 Sentence Case；动词优先去名词化（用 `analyze` 替代 `perform an analysis of`）；列表各项保持语法平行；首现缩略词展开全称。

## 6. 交付前自审清单

- [ ] **去机械化**：已清除主持报幕、空洞升华、“不是……而是……”对照与通胀黑话。
- [ ] **标题合规**：全篇序号通道唯一，无“几大原则/几大核心”量词堆数字，标题末尾无句号、冒号等点号。
- [ ] **混排与引号**：汉字与西文/数字/行内代码间留有半角空格；中文引号（`“”` 或 `「」`）前后风格统一且未强求 `「」`。
- [ ] **标点外置**：`**` / `~~` / `<u>` 内侧未紧贴标点，跨度内全角标点 ≤ 2 个已移至外侧，> 2 个已退回纯文本或拆分加粗。
- [ ] **协议层合规**：Tier 1 文档保持零 HTML 装饰标签、Fenced 代码块均带语言标识、不依赖客户端私有渲染方言。
